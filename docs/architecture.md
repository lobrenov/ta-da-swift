# Ta Da architecture

How the app is built. The file format and writing rules are in `docs/file-format.md`; the design system is in `docs/design/design-framework.md`.

## Layers

- **TaDaCore** (`Packages/TaDaCore`, local package): the model, parsing, surgical writes, the index, queries and storage. Foundation, swift-markdown 0.9.0 and Yams 6.2.2 only; no UI.
- **TaDa** (`TaDa/`, app target): SwiftUI views over an `@Observable` `AppModel`. macOS 26 and iOS 26 minimum; on the Mac, App Sandbox with user-selected read/write. The model, theme, live editor, folder handling and the document's title, body, banner and footer build for both; the Mac's views are behind `#if os(macOS)` and the iPhone's are in `TaDa/iOS/`.
- **TaDaMarkdown** (`Packages/TaDaMarkdown`, local package): the Live editor, from swift-markdown-engine 0.13.0 under Apache-2.0, for macOS and iOS. Parsing, styling, layout, input and the text-delegate path are shared; `Platform/Platform.swift` names the AppKit and UIKit types, and `TextView/iOS/` holds the iOS editor. Its `ORIGIN.md` lists the changes.

The workspace `TaDa.xcworkspace` holds the project, TaDaCore and TaDaMarkdown; the test plan `TaDa.xctestplan` runs TaDaTests, TaDaCoreTests and TaDaUITests.

## Runtime

- **Launch**: resolve the folder's security-scoped bookmark, scan it recursively off the main actor, parse every file into a `VaultIndex`. A change to a file patches only that item's entries in the index's title and link maps (tasks by project title, projects and tasks by area title, and files by the image filenames they embed, which `embedders(of:)` reads with counts). `parent(of:)` is a task's project, else its area, or a project's area; `area(of:)` reaches a task's area through its project. `AppModel` works out the Today groups (`grouped`), Loose and Upcoming lists, the loose projects and the areas with their projects from the index's `Queries` (which take an injected `today`) once per change, and views read those; a refresh applies all its changed files as one change. Each query applies a per-item test (`isInToday`, `upcomingEntries(of:after:)`, `isLoose`), which `FileInspector` uses for one file, and `progress(of:)` counts any project's tasks.
- **Editing**: `OpenDocument` holds the selected file's whole text. Typing, property edits and checkbox clicks change that text, which is reparsed into the index. It saves 600 ms after the last change, and also before switching files, when the app deactivates and on quit (on iOS, on entering the background, under a background task). Files load one at a time: each selection waits for the previous load, which is skipped if it hasn't started. `AppModel` does its file work off the main actor through `run`. Quitting, including by closing the window, waits for the save: `AppDelegate.applicationShouldTerminate` returns `.terminateLater`. A checkbox click in a row whose file isn't open does a coordinated read, a surgical edit and an atomic write.
- **Saving** is guarded: Ta Da writes only if the file still holds the text it last read or wrote.
- **Trash**: deleting moves a file into `.trash/` in the folder (created when needed); a project takes its linked tasks, and an area its projects, their tasks and its own tasks. Deleting an area, or files that embed images, first sets `AppModel.trashConfirmation`; with no images the Mac and iPhone show it as a question (`TrashConfirmationText`), and otherwise as `DeleteFilesDialog`, which lists each image under the first file that embeds it, ticked unless a file that stays embeds it. `confirmTrash(_:images:)` deletes, moving the ticked images to `.trash/attachments/`. `asksBeforeTrashing(_:)` tells the iPhone's menus to wait for the answer before leaving the file. `AppModel.trash` lists the Ta Da files there, reloaded on each refresh. Restoring moves files to `tasks/`, `projects/` or `areas/` and brings back their parents (recreated by name if deleted forever, relinked if a name changed); Delete Forever and Empty Trash move them to the system Trash (on iOS outside iCloud Drive, where that isn't supported, they delete them; the Mac never deletes); a file that can't be removed is reported and the rest still go. Attachments go to `.trash/attachments/` (`Vault.moveAttachmentsToTrash`), and restoring a file takes the trashed attachments it embeds (`TrashedAttachment.attachment(named:trashedAt:in:)`, and its embeds follow an image restored under another name), and removing a file takes those that no other trashed file or file in the folder embeds (`TrashedAttachment.attachments(of:in:others:live:)`). The rules are in `docs/file-format.md`.
- **Logbook**: completed (Done or Cancelled) tasks and projects move into `.logbook/<yyyy-MM>/` by their `completedDate` (`Vault.log`). The scan reads `.logbook/`; the index holds logged files (`Item.isLogged`) so links to them resolve, after a file of the same title that isn't logged, but its task, project and area lists, the files filed under a parent, Search and the link menu leave them out, and a project's progress counts them. `AppModel.logIfDue()` logs `VaultIndex.filesToLog(completedBefore: today)` once a day (the day kept in the settings), when the folder opens and when `today` changes, and puts back logged files reopened elsewhere and logged projects that have open tasks (`VaultIndex.loggedProjectsWithOpenTasks`), as Doing; `logNow()` logs everything, first asking about a completed project with open tasks. `AppModel.logbook` is the logged files and the completed ones not logged yet; `LogbookGroup` groups them for the Mac's `LogbookView` and the iPhone's `PhoneLogbookScreen`. Setting a logged file's status to an open one puts it back (`Vault.unlog`) to `tasks/` or `projects/`, with its logged project as Doing; a task that's open or reopened does the same for its logged project. Completing or cancelling a project that has open tasks first sets `AppModel.completionConfirmation`, shown as `CompletionDialog` (a sheet, from `ContentView`) on the Mac and a confirmation dialog (from `PhoneRootView`) on iPhone; `answerCompletion(_:tasksAs:)` sets the project and its open tasks. The rules are in `docs/file-format.md`.
- **Outside changes**: `VaultWatcher` (FSEvents on the Mac; on iOS, file coordination on the folder) and app activation both trigger `refresh()`, which compares modification dates with the last scan and reparses only changed files. The open document reloads if it has no unsaved edits. With unsaved edits, `DocumentBanner` offers keep mine / use the file on disk, save again / discard after a deletion, or keep this / use the other iCloud version (`Conflicts` writes the file, marks the conflict resolved and removes the other versions in one coordinated write). Leaving the file, quitting or (on iOS) going to the background with a choice still open writes the edits to `<title> (unsaved edits).md` beside it. The open file is presented to file coordination (`FilePresenter`): another app's coordinated read or merge, iCloud Drive's uploads among them, first saves the edits, and a coordinated move or rename (Finder, iCloud) is followed. A rename without coordination (Obsidian, Terminal, git) shows as a deletion. On iOS the watcher and the open file's presenter are removed on entering the background, after the save, and added again (before the refresh) when the app becomes active, since a suspended app can't answer coordination. On iOS, files and images iCloud Drive hasn't downloaded are hidden `.Name.md.icloud` placeholders (an image's is listed in `attachments` under its real name); opening the folder and each refresh ask for them (`Vault.downloadPlaceholders()`), and each joins the index once it arrives.

## Themes

A theme set pairs a light and a dark scheme. `AppModel.theme` is the set's dark scheme when the appearance is Dark, or System while macOS is dark (`systemIsDark`, from `NSApp.effectiveAppearance`, observed with KVO), otherwise its light scheme. With a scheme per appearance on, `lightScheme` and `darkScheme` replace the set's pair. Each window's appearance follows the shown scheme (`preferredColorScheme`), so a dark scheme in light mode (Dracula) still gets dark controls, context menus, alerts and popup menus; menus in the menu bar follow macOS. All five settings persist in `UserDefaults`.

## Window

`SidebarSplitView`: `NavigationSplitView { SidebarView } detail: { WorkspaceView }`. When the window (its width, from `NSWindow.didResizeNotification`) is narrower than the sidebar plus `WorkspaceView.minWidth` (the browser's 320 and the document's 360), the sidebar slides away, as the window opens or resizes, and comes back when there's room unless it was hidden by hand; shown in a narrow window, it slides away again. Once it has slid away, the split view's sidebar button gives way to an identical one beside the window's buttons, since the split view's own would show the sidebar beside the workspace. In a narrow window the sidebar button and View ▸ Toggle Sidebar (⌃⌘S) float the sidebar over the workspace instead; a click outside it or any pick in it hides it. Search Files (⌥⌘F) floats the hidden sidebar with its search field focused. `SidebarState` holds whether the sidebar is docked, hidden or floating. While the sidebar is hidden, at any width, a two-finger trackpad swipe to the right (40pt, mostly sideways) floats it too, unless a scroll view under the pointer can scroll left; it slides in from the left. A swipe to the left hides the floating sidebar, or the docked one when the pointer is over it. The window is at least `WorkspaceView.minWidth` wide. Settings (⌘, or the sidebar's Settings row) is the `Settings` scene: `SettingsView`, 900×640, with Vault, Themes and Editor pages. The workspace shows:

- Today, Loose tasks, the Logbook, a project's tasks and an area's page (`AreaBrowserView`): the browser list beside `DocumentPane`. The browser takes half the width, from 320 to 460, leaving `DocumentPane` at least 360.
- Upcoming: the agenda beside the month calendar when nothing is selected, otherwise the agenda beside `DocumentPane`.
- A project's or area's own file: `DocumentPane` (with `ProjectDocumentView` for a project) across the workspace.
- Search: `SearchResultsView` beside `DocumentPane`.
- Trash: `TrashView` across the workspace.
- Source mode: `DocumentPane` with the Source editor and `FileInspector` across the workspace, until the selection clears.

A right-click (or control-click) on a sidebar area or project, an area page's project row or a task row in any list opens `FileMenu`: a compact themed panel at the pointer, with the row ringed in `accent`. It offers Move, Schedule, Set Deadline…, Reveal in Finder and Delete; on an area New Task and New Project in it, Open Area File, Reveal in Finder and Delete; or Restore, Reveal in Finder and Delete Forever in Trash. A right-click on a picked file acts on every picked file. Move opens the project menu (the area menu for a project), and Schedule and Set Deadline… the due date's or deadline's calendar, at the pointer in its place, with the row still ringed. While open it takes ↑↓, ↵ and esc.

Moving tasks to a project or area: the file menu's Move, ⇧⌘M and dragging all act on `AppModel.moveTargets(for:)`, the right-clicked or dragged row (every picked task when it's one of them) or, for ⇧⌘M, the picked tasks or the open one, in list order and without projects. ⇧⌘M sets `AppModel.propertyMenuRequest`, and the open task's project chip, or else the first picked row (`.taskDrag`), opens the move menu under itself. Projects move to an area the same way, through `AppModel.areaTargets(for:)` and the area menu. Task rows in every list but Trash are draggable (`.taskDrag`) as `TaskFile`s, their file URLs, in `WorkspaceView`'s drag container (`.taskDragContainer`), which drags every picked task when a picked row is dragged and lets other apps only copy; the sidebar's projects, areas, Loose tasks and Today take them (`.taskDrop`), finding the tasks with `Vault.path(of:)`, filing them under the project or area with `AppModel.setParent(_:of:)`, emptying their parent, or making them due today with `AppModel.makeDueToday(_:)`. An area also takes dragged sidebar projects. Files already there aren't written.

Setting dates: the file menu's Schedule and Set Deadline…, ⌘S and ⌘D act on `AppModel.dateTargets(for:)`, the same files as a move but with projects. ⌘S and ⌘D set `AppModel.propertyMenuRequest`, and the open file's due date or deadline chip, or else the first picked row, opens the calendar under itself. For several files the calendar fills a date, and shows the other date's dot, only when they all agree; `AppModel.setDate(_:to:of:)` writes the files whose date changes.

Browser lists share their selection: each registers its rows with `.arrowKeySelection(model, paths:, allowsMultipleSelection:)` (the lists beside the document through `BrowserColumn`, which also sets their header and padding), and rows show `model.isSelected(_:)`, call `model.click(_:)` and add `.fileMenu`. Every list allows several (Search picks tasks only, since a project opens its page): shift-click picks a range and ⌘-click adds or removes a row (`AppModel.multiSelection`, or `trashSelection` in Trash). The document pane shows "N tasks selected", and Upcoming keeps its agenda column while tasks are picked. In Trash a plain click picks one file. The list keys go to a `ListKeyView` behind each list, an AppKit responder that takes the keyboard when the list appears, when nothing has it and when a row is picked, but never from a text view, or for a new file whose title is about to take it.

A project's browser folds its Open and Completed groups from their headers, and an area's its Projects, Tasks and Completed (Completed starts folded). `AppModel.foldedGroups` keeps the folded ones per project or area path in the settings and follows a rename; a folded group's rows leave the arrow-key list. Its header shows the project's chips through `PropertyChipRow`, and its title, an area page's title and the project page table's titles are `InlineTitleField`s, which rename with `AppModel.rename(_:to:)`. The table's New linked task calls `AppModel.newLinkedTask(in:)`, which sets `titleFocus` so the new row's title starts editing without opening the task.

## iPhone

`PhoneRootView` is a `TabView` of Today, Upcoming, Loose, Projects and Other, each a `NavigationStack` whose path lives in `PhoneNavigation` (`@Observable`, in the environment), with the date, move and area sheets over them.

- `PhoneScaling.swift`: Dynamic Type. `.scaledFont(size:weight:design:)` takes the design's point size as the size at the default text size and scales it with the user's (relative to body); `.scaledMinHeight(_:)` does the same for a control's height that pairs with text. The week strip, the date sheet's month grid, the large titles and the picking bar (with the room the lists leave for it, `PickingBarClearance`) stop growing at xxxLarge. Icons in fixed slots (the floating +, the pull-search field, the swipe's pill, the onboarding checkmark) and the file's title and the editor's text stay fixed.
- `PhoneNavigation.swift`: tabs, routes (file, project, area, settings section, logbook, trash), the sheet, the move and area sheets' rows (`PhoneMoveRow`), picked rows and `Haptic`, played through `.sensoryFeedback` when Settings ▸ Haptics is on (`AppModel.haptics`). It and `AgendaEntry.Kind.changes` (the dates the date sheet writes) build on the Mac too, so `PhoneNavigationTests` run with the Mac's tests; the rest of `TaDa/iOS/` is `#if os(iOS)`.
- `PhoneList.swift`: what every list shares: the title and subtitle at the top of the list (the navigation bar shows the title once it scrolls away), pull to search, the floating + and the "…" menu with Search and Select (Search is also a VoiceOver action on the list). A tap on the list with the search field open and empty closes search; a screen pushed over the list keeps its search, and switching tab resets it. Only the list on screen sets `PhoneNavigation.pickable`, and picked rows it stops showing are unpicked.
- `PhoneSearchField.swift`: pull to search. `ListSearch` is a list's state (pull distance, open, query); each tab's `PhoneSearchStack` draws the field of the list on screen (registered through `SearchHost`) above the navigation bar, so it takes taps. Past 60 pt the pull's grey pill snaps into an accent dot with a tap; letting go there grows the dot into the field in the bar's row, with a close button in place of the "…", and the keyboard comes when the field lands. It searches every file; its results don't swipe to pick. `pullToSearch(_:)` gives a scroll view the pull, the tap that closes an empty search, the VoiceOver action and the registration; lists, file screens and Trash use it, and a file screen's toolbars give way to the field while it's open.
- `PhoneScreens.swift`: Today (tasks with no parent, then loose projects, then each area's own tasks and projects) and Loose, Upcoming (a week strip over day headers), Projects (loose projects, then each area with its projects; Completed folds), a project's tasks (Open and Completed fold, with `AppModel.isFolded`) and an area's page (`PhoneAreaScreen`: Projects, Tasks and Completed fold; its More menu has New Task, New Project, Area File, Rename, Share… and Move to Trash).
- `PhoneRows.swift`: task, project and area rows and headers. Press and hold opens `PhoneFileMenu`: Complete, Today and Tomorrow, Status, Schedule…, Set Deadline…, Move… (the move sheet for a task, the area sheet for a project), Share…, Select and Move to Trash; on an area, Area File, Share… and Move to Trash.
- `PhoneFileScreen.swift`: a file pushed from any list. Title (`TitleField`), chips (project or area, due date, deadline) that open the sheets, a quiet line with its kind, status and created date, the body in `BodyEditor` or the whole file in a Source `TextEditor`, and a project's linked tasks. The top bar has the Live/Source toggle and a More menu (Done while its title, body or source has the keyboard); the bottom toolbar has the status checkbox (a tap completes or reopens; press and hold lists the statuses, which VoiceOver also offers as actions), Schedule, Deadline, Move (tasks), Share and Trash, and an area's only Share and Trash. It sets `model.selection` when it appears and clears it once the screen is popped (a tab switch, or a screen pushed over it, leaves the file open, and the same file pushed twice stays open until both are popped); it shows and edits only the document `AppModel` has open.
- `PhoneSheets.swift`: `PhoneDateSheet` (due date or deadline, quick days and a month grid) and `PhoneMoveSheet`: Move for tasks (search, Loose tasks, loose projects, then each area and its projects, New Project…, New Area…) and Area for projects (No area, the areas, New Area…), with Create Area for an unresolved one; for one file or the picked ones. Each writes on ✓.
- `PhonePicking.swift`: swipe to pick. A `UIPanGestureRecognizer` that begins only for a leftward, mostly horizontal pan slides the row left, opening a pill in the gap with a check (an xmark when it unpicks), bright past 26 pt; letting go past 26 pt picks the row, or unpicks it while picking (unpicking the last row ends picking), and the row springs back. While picking, Select All, the count and Done replace the navigation bar, and the action bar (Complete, Schedule, Move, More, Delete), a glass capsule in the tab bar's place, replaces the tab bar.
- `PhoneLogbook.swift`: the Logbook, grouped as the Mac's (`LogbookGroup`), with Log Now in the bottom bar.

On iOS the live editor (`LiveEditor`) uses 17 pt text; press and hold on a checkbox or callout title opens `CheckboxMenu` or `CalloutMenu` as popovers, with a medium tap. A typed `/` stays text: there is no slash menu. A typed `[[` or `![[` lists its choices (`PhoneLinkList`) above the keyboard bar, which grows to hold them; a tap picks one, as ↵ does on a hardware keyboard. The wikilink button types `[[` through `SlashCommandProxy.type(_:)`, so Autocomplete's switches apply as they do to typing; with Wikilinks on it wraps a selection, and right before `]]` it steps over it. ## Editors

- **Live**: `LiveEditor` runs the engine with `.fitsContent` height inside a SwiftUI `ScrollView`, between the title and properties above and the footer (and a project's linked-tasks table) below. The engine's binding reads and writes only the body; it is spliced back after the frontmatter block. Theme tokens map to `MarkdownEditorTheme`; `TaskCheckboxStyle` takes its strikes and click transitions from `Checkbox.State` and its tints from `Theme.checkboxTint`, and `InlineCheckbox` draws the boxes; wikilinks resolve by `WikiLink.title` against the index's `titles`. A click on a link (on iPhone a tap, unless the caret touches it) opens its file: on the Mac a project or area as its page, and a task in its project's or area's page or in Loose tasks (`AppModel.openLink(to:)`); on iPhone the file is pushed. Renaming a file points the links to it in other files' bodies at the new title (`Vault.retargetLinks`), the open file's in place. The properties' meta line ends with “N backlinks”, a menu of the files that link here; the Mac's footer shows when the file was modified.
- **Source**: `SourceTextView`, a TextKit 1 `NSTextView` with a line-number ruler and a current-line highlight. It edits the whole file, frontmatter included. `SourceHighlighter` (in TaDaCore, on `FrontmatterSplitter`, `WikiLink` and `LocalDate`) colours it by role (key `accent`, value `fg`, string `done`, date `due`, heading `strong`, punctuation and checkbox `muted`, done checkbox `done`, link `link`) and reruns over the whole file after each edit.
- **Autocomplete**: `AppModel.autocomplete` holds Settings ▸ Editor's switches (Brackets, Text formatting, Wikilinks and embeds, all on by default), kept in the settings as one dictionary. `LiveEditor` passes them to the engine's `ListStyle`. A typed `(`, `[` or `{`, a formatting marker (`*`, `**`, `_`, `__`, `~~`, `==`, `` ` ``) or `[[` adds its closer, and typing that closer steps over it while the caret stays between the pair. Markers pair only between words and outside code; a single `*` at a line's start stays a bullet, a space straight after a marker removes its closer, and a run past the longest marker (`***`, ```` ``` ````, `~~~`, `===`) stays unpaired.
- **Slash menu**: `/` in the Live editor opens `SlashMenu`, a themed list of `SlashCommand` formats in a `PopupMenu`: a borderless panel that places itself under its anchor and closes on a click elsewhere or a scroll. The checkbox, file and property menus use it too.
- **Images**: `LiveEditor` gives the engine `AttachmentImages`, which finds an embed's image among `AppModel.attachments` (the folder's images, reread on each refresh) as `Vault.attachmentPath(for:in:)` does and decodes it at up to 2048 pixels. An image alone on its line draws at its pixel size in points, fitted to the editor's width, with rounded corners, and stays drawn as the caret passes; the caret steps over its hidden `![[ ]]`, and ⌫ after it removes the embed. On the Mac a `</>` button over a hovered image ("Show markdown") shows the source until the caret leaves the line. A missing image's name is muted at 60% with a dashed underline. A pasted image, or an image file dropped from Finder on the Mac, goes through `AppModel.embed(_:)`: image data is saved as `attachments/Pasted image <time>.png` (on iPhone in its own format), a file from outside the folder is copied into `attachments/` keeping its name, and an image already in the folder is embedded where it is. `embed(_:)` returns the embed straight away, from the names `attachments` already holds, and writes the file off the main actor (`savingImage`). On the Mac only the image types in `Vault.imageExtensions` paste as files; another image file pastes as PNG data. The embed goes on its own line.
- **Embed menu** (`EmbedMenu.swift`): on the Mac a click selects an image (an accent ring) and a right-click opens Copy, Cut, Rename…, Reveal in Finder and Delete in the file menu's panel (`FileMenu.show(_:at:in:theme:onClose:)`); ⌘C, ⌘X and ⌘⌫ do the same on a selected image. On iPhone a press and hold opens Copy, Cut, Edit Markdown, Rename…, Show in Files and Delete. Copy puts the image file (which a paste in Ta Da embeds as it is) and its data, read off the main actor, on the pasteboard; Cut also removes the `![[ ]]` as one undo step. Rename and Delete set `AppModel.imageDialog`, shown by `ImageDialogs.swift` (sheets on the Mac; an alert and a sheet on iPhone). `renameAttachment(_:to:)` renames the file in its folder, keeping its extension and refusing another image's name, and retargets every embed that showed it (`Vault.retargetEmbeds`), the open file's in place. `trashAttachment(_:)` moves the image to `.trash/attachments/`; its embeds stay and show as missing. Trash lists each trashed file's images under it (`trashedAttachmentsByFile`, the images that go with it alone), picked with it, then the other trashed images (`looseTrashedAttachments`), with the files whose embeds are missing them. Image thumbnails (`ImageThumbnail`, in the dialogs, Trash and the delete questions) decode off the main actor into `ThumbnailCache`, which the link menu's rows share.
- **Link menu**: `[[` opens `LinkMenuController`'s `PopupMenu` under it, on the folder's files; `![[` on its images (`Vault.attachmentPaths()`, read once per query). The engine reports both as slash queries with a `link` or `embed` trigger; `BodyEditor` passes a `LinkMenuSource` (the index, the folder, `AppModel.recentFiles` and the open file, which is left out). `LinkMenuSearch` ranks by `LinkSearch`: an empty `[[` lists the last eight files opened (every file by title when none has been), and a query searches the recent ones first, then the rest by title. A pick replaces the query and its `]]` with `[[Title]]` or `![[name.png]]` as one undo step, with the caret after it. `AppModel.recentFiles` keeps nine paths in the settings, follows renames, and adds each file as it opens.
- **Checkbox menu**: a right-click on a Live editor checkbox opens `CheckboxMenu`, the same kind of panel listing every marker (subtasks, then icons) with its box drawn by `InlineCheckbox`. While open it takes ↑↓, ↵ and esc.
- **Callouts**: `LiveEditor` gives the engine a `CalloutStyle`, so `> [!type]` quotes draw as panels (types and aliases from `CalloutType`, icons from `CalloutIcon`). A click on a foldable callout's icon, chevron or the row past its title folds or opens it on screen only; the file keeps its `+` or `-`, and a folded body shows while the caret is in it. A right-click on a title line opens `CalloutMenu` under the icon, with the callout ringed: picking a type or fold edits only the text between `[!` and `]` or the character after it, as one undo step. While open it takes ↑↓, ↵ and esc.
- **Properties**: `PropertyChips` shows status, the parent (a task's project or area, a project's area; struck through when unresolved), dueDate and deadline as chips under the title (an area has none), and the type, createdDate and completedDate in a line below. A chip opens its picker under it through `PropertyPicker`. Status, move and area are `PopupMenu`s: they take ↑↓, ↵, esc and typed letters, and the move and area menus' search fields take the keyboard. The move menu lists Loose tasks, loose projects, then each area followed by its projects; the area menu No area and the areas. For several files a menu ticks a row only when they all agree. New Project and New Area create the file and file the tasks under it (`AppModel.newProject(named:linking:)`, `newArea(named:filing:)`); Create Area makes the area an unresolved link names. A date opens `CalendarPicker`, a month in a `PopupPanel` that takes ←↑↓→, ↵ and esc. VoiceOver gets each chip's choices as actions on the chip.
