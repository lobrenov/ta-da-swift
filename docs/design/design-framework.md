# Ta Da design framework

Mirrored by the Claude Design System artifact https://claude.ai/artifact/GkKXeVHXv9XMGMWWacPppz (last synced 2026-10-16, version 1792133435-196d; it shows one colour scheme per theme set, eight of the nine). This folder is the copy the repo follows: `tokens.json` holds the values, `components/<Name>/README.md` the component guidelines and `components/bundle.css` their reference CSS. [In the app](#in-the-app) maps each part to its Swift code, and [As built](#as-built) lists where the app differs from the guidance.

The app's screens, menus and states are mocked up on the Claude Design canvas https://claude.ai/artifact/A7c33hg9HUKz41u3wbki3V.

The design system for Ta Da, a Swift-native task manager where every task and project is a plain markdown file in iCloud Drive. The interface is quiet chrome around the files: neutral panes, one accent, and colour reserved for meaning. Every colour comes from an iTerm2 colour scheme, so the whole app rethemes from one file.

## Principles

1. **The file is the truth.** The UI shows what is in the markdown and frontmatter and nothing it cannot write back. YAML keys appear exactly as written (`dueDate`, `deadline`) in the `mono` family.
2. **Colour means something.** Neutrals carry the layout. Hue appears only as a signal: a status, a date kind, a link. If a colour is decorative, remove it.
3. **Signals live on glyphs, not text.** Status and date colours sit on checkboxes, dots and 12px icons; text stays `fg` or `muted`. This keeps every theme readable, light ones included.
4. **One accent per view.** `accent` marks the primary button, the caret and project progress. Nothing else competes with it.
5. **Calm density.** 32px rows, 13px UI text, hairline borders. No shadows inside the window (menus float above it and carry the only one), no cards for content that is already a list.

## Colour

Fifteen semantic tokens, defined for six bundled iTerm2 schemes (values from iterm2colorschemes.com), with border, code and muted derived by the token rules. The schemes pair into three theme sets, each a light and a dark scheme: Ayu (Ayu Light, Ayu Mirage), TokyoNight (TokyoNight Day, TokyoNight) and Catppuccin (Latte, Mocha). Ta Da shows the set's light or dark scheme with the macOS appearance, or always one of them when the appearance is set to Light or Dark. Ayu is the default set.

| Token | Role | iTerm2 source |
| --- | --- | --- |
| `bg` | Window and editor ground | Background Color |
| `side` | Sidebar, title bars, panel headers | Background, darker |
| `surface` | Selection, active item, pressed chip | Selection Color, else Background + 16% Foreground |
| `border` | 1px hairlines | Background + 10% Foreground |
| `code` | Raw markdown lines, inputs | Background + 5% Foreground |
| `fg` | Body text | Foreground Color, lifted to 5.5:1 |
| `strong` | Headings, selected titles | Foreground, 45% toward black or white |
| `muted` | Meta, keys, done titles | Ansi 8, lifted to 4.5:1 |
| `accent` | Primary action, progress, caret | Ansi 4 Blue |
| `due` | dueDate glyphs, Agenda icon, Agenda dots | Ansi 3 Yellow |
| `deadline` | deadline glyphs, destructive | Ansi 1 Red |
| `done` | Done status, Logbook | Ansi 2 Green |
| `doing` | Doing status | Ansi 6 Cyan |
| `blocked` | Blocked status | Red → Yellow, 50% |
| `link` | [[wikilinks]], project values | Ansi 5 Magenta |

Importing a new `.itermcolors` file fills these by the same mapping. When a scheme's Ansi 8 is too dim, `muted` is lifted until it passes 4.5:1 on `bg`; `fg` is lifted to 5.5:1 the same way (TokyoNight Day).

Contrast rules: text uses only `fg`, `strong` and `muted`. `due`, `deadline`, `done`, `doing`, `blocked` are for icons, dots, borders and fills; on light themes several fall below 4.5:1 as text. `accent` and `deadline` fills carry `bg`-coloured labels at 600 weight or more.

## Typography

Two families. `sans` is the system face (SF Pro on macOS), because Ta Da is a native app. `mono` is JetBrains Mono (Google Fonts) with SF Mono and Menlo as fallbacks, used for everything that is literally in the file: YAML keys, paths, checkbox syntax and Source mode.

- View titles (`title-view`, 26/32 bold) sit 44px below the window top with their domain icon at 24px.
- Task titles use `task` (13.5px), on one line with the row's glyphs and date in `muted`.
- The editor renders markdown at `body-editor` (14/23) and source at `source` (13.5/23), so toggling Live and Source does not reflow lines.
- Uppercase is only for `label` (11px, 600, 0.06em tracking): PROJECTS, TOKENS.

## Layout

- **Window.** Sidebar `size-sidebar` (240px) on `side`, then the browser pane `size-browser` (460px), then the editor filling the rest. Logbook, Trash and other archive views are single-pane: sidebar plus one pane with a 760px max content width and `space-10` (64px) padding.
- **Sidebar order.** Search, Agenda, a 10px gap, Logbook, Attachments, Trash, the Tasks | Tags | Notes switch and its list (Loose tasks, loose projects and each area with its projects; or the tag tree; or the notes folders), then the folder line, Settings (⌘,) and the New buttons at the bottom.
- **Settings window.** 900×640 on `bg` with a 46px `side` title bar. A 200px `side` nav (Vault in `accent`, Themes in `link`, Editor in `doing`, Daily notes in `done`, Integrations in `deadline`, Notifications in `blocked`, Hotkeys in `due`) beside the page: a `title-dialog` title, a `muted` line under it, then label-and-control rows (labels `muted`, 84–92px wide), bordered 10px panels and uppercase section labels.
- **Editor.** 46px toolbar (`size-titlebar`) with the file path as a mono breadcrumb and the Live/Source switch on the right. Then title, properties, a hairline, and the body.
- **Rhythm.** Rows 32px; gaps from the spacing scale (4, 6, 8, 10, 12, 16, 20, 28, 44, 64). Groups of rows are separated by a group header with a 1px `border` underline, not by cards.
- **Radius.** 4px checkboxes, 7px rows and controls, 10px panels and menus, 12px windows; chips are capsules (`radius-full`).
- **Scrollbars.** Thin, transparent track, `surface` thumb, `muted` on hover.

## Iconography

- 16px line icons on a 16-unit grid, 1.6 stroke, round caps and joins, `currentColor`. 12px in rows, 24px next to view titles. No emoji anywhere.
- Each domain has a fixed icon colour: Agenda `due` (calendar), Loose tasks `accent` (tray), Logbook `done` (book with tick), Attachments `link` (photo), Trash `muted` (bin). Projects use a progress pie in `accent`.
- Dates: calendar glyph in `due` for `dueDate`, flag in `deadline` for `deadline`. A task appears on both dates in an Agenda week, each row showing the date it is listed for.

## Editor markdown

The Live editor draws the file's markdown at `body-editor` (14/23) and keeps every marker in the file. Guidelines: `components/Markdown/README.md` and `components/Callout/README.md`.

- **Headings** step down from `heading-1` (20/28) to `heading-6` (13/20, `muted`); all sit below the file title (`title-file`, 23px).
- **Bubbles.** Inline code and highlights are rounded spans: `radius-sm` corners, 2px above and below, rounded again on each line they wrap onto, text in `strong`. Code sits on `code` with a 1px `border` ring, in `code-text` (12.5px mono). A highlight is `due` at 30% (26% on dark schemes), the one place `due` fills behind text.
- **Blocks** use `radius-lg`: code blocks (`code` with a `border` ring and the language top right in `muted`), tables (a `border` frame, header row on `code`), images and callouts.
- **Links**: `[[wikilinks]]` in `link`; markdown links in `link` with a 45% underline; unresolved wikilinks in `muted` with a dashed underline.
- **Lists** indent 27.5px a level, with `muted` bullets that change by depth (filled circle, circle, filled square, diamond) and `muted` numbers. Task lines draw the inline checkboxes above.
- **Quotes** are `muted` text beside a 3px rounded `surface` bar.
- **The caret's line** shows its markdown in mono 13px on `code`, `radius-sm`, markers in `muted`; every other line stays drawn.

### Callouts

Obsidian's callouts: `> [!type] Title` opens one, and the following `>` lines are its body. The icon carries the type's colour; the panel is that colour at 9% (14% on dark schemes) with a 24% ring (30%), so text keeps `strong` titles and `fg` bodies. `+` or `-` after `]` makes it foldable, open or folded, with a `muted` chevron on the right. A right-click on the title line opens the callout menu.

## Writing

- Sentence case for labels and menus; title case only on buttons, as macOS does ("Log Now", "Empty Trash").
- Name things by what people see: "Loose tasks", "Logbook", "Trash", never "orphan files" or "archive directory". Folder names (`Ta Da/Logbook/`, `.trash/`) appear in mono where the file location matters.
- Dates: "Today", "Tomorrow", "Tue 6 Oct" in rows and property chips; ISO `2026-10-06` in source.
- Buttons state the result and counts update live: "Restore 2 Items". Confirmations say what is permanent and where: "Permanently delete 4 files from iCloud Drive?"
- A label, subtitle or count never defines the thing it names: Loose tasks shows its count as a project row does, not "4 with no project or area".
- Extra text states only what the screen doesn't show: an error, a consequence that is permanent or happens elsewhere, or the fix.
- An empty state is a title alone ("No loose tasks", "Trash is empty").
- Settings pages have no summary line. A row has a caption only when its effect can't be seen.

## Components

Plain CSS classes in `components/bundle.css`, prefixed `td-`, built on these tokens: Checkbox, TaskRow, SidebarItem, Chip (property, tag, filter and Group chips), Button, Menu, Markdown, Callout. Each has guidelines in `components/<Name>/README.md`. In the Swift app they map to SwiftUI views; the classes here are the reference for spacing, states and colour roles.

## As built

Where the app differs from the guidance above:

- **Mono type** is the system monospaced font (SF Mono): `.monospaced` in SwiftUI, `NSFont.monospacedSystemFont` in the editors. JetBrains Mono is not bundled.
- **Icons** are SF Symbols: Agenda `calendar`, Loose tasks `tray`, Logbook `book.closed`, Attachments `photo`, Trash `trash`, due `calendar`, deadline `flag`, subtasks `checklist`, repeat `repeat`, a note `doc.text`, a notes folder `folder`, Loose (notes) `tray`. A project's icon is `ProgressRing`, a 14pt ring with a pie, or `checklist` for an Ongoing project; an area's is `AreaIcon`. The file menu uses `folder` (Move), `calendar` (Schedule), `flag` (Set Deadline…), `tag` (Tags…), `arrow.up.forward.square` (Reveal in Finder), `trash` (Delete), `arrow.counterclockwise` (Restore) and `xmark.bin` (Delete Forever). The property chips use `chevron.down` (status) and `plus` (a missing key), the move menu `magnifyingglass`, `tray` (Loose tasks), `AreaIcon` (areas), `ProgressRing` (projects) and `plus` (New project, New area, Create Area), and the area menu `xmark` (No area).
- **Sidebar** order: Search, Agenda (with today's open-task count), an 8pt gap, Logbook, Attachments (with the folder's size in place of a count), Trash, the Tasks | Tags | Notes switch, then Loose tasks, loose projects and each area (title order) with its active projects under it, not indented and with no section label (or Untagged and the tag tree, or Loose and the folder tree), then the folder line ("Watching · <folder>", its icon in `done` while the folder is watched), Settings and New task / New project / New area (New note / New folder in Notes). Area rows have no ring and no count, and don't fold. Project rows are 30pt tall. The sidebar is 200–340pt wide, 240pt by default.
- **Panes**: the browser pane is 320–460pt wide until its rule is dragged, then the dragged width (at least 320pt), shared by every browser; the document pane keeps at least 360pt. The Agenda's browser column holds its strip above the day or week list, and the period's note (or its create row) is in the document pane. Source mode takes the whole workspace, with text up to 760pt wide and a 300pt file inspector.
- **Task row** is one line, 32pt on the Mac: the checkbox, the date, the title (truncated, the full title in its tooltip), the glyphs (11.5pt) and the place. The date is a 12pt pill with no icon. On iPhone it is at least 46pt, with a 22pt box, a 17pt title, 14pt glyphs and a 15pt place and date. The glyphs are `doc.text` (the body has more than checkboxes), `checklist`, `repeat` and `tag`, in that order, each with its detail in its tooltip; contexts aren't shown. The date is the deadline when set, else the due date, as a pill tinted `accent` (14% light, 22% dark, text `fg`), or `deadline` when overdue or a deadline today, read "Today", the weekday for the next six days ("Thu"), else "29 Oct" ("29 Oct 2027" in another year), its tooltip and VoiceOver label giving the kind and full date; in the Agenda a deadline reads "Today", "N days left" or "N days late", a due date shows only when overdue, and a week's rows show the date they're listed for. The place shows in the Agenda's day under Status and Open and in its week. The place truncates first, then the glyphs drop (keeping their VoiceOver labels), before the title truncates. Mac search results use the row without a place; an iPhone search result keeps its title over its place and the matching summary.
- **Inline checkboxes** draw the design's checkbox glyphs and tints, in a 16pt box (1.5pt stroke, 4pt outer radius), 10pt from the text. Task rows draw the same boxes: Blocked uses the `[B]` bar. `[X]` draws as `[x]`. `[x]`, `[X]` and `[-]` strike their text in `muted`. `[B]` is not a body marker; Blocked is a frontmatter status only.
- **Buttons**: Empty Trash, Log Now and the completion sheet's default are the primary buttons; Empty Trash's confirmation's Empty Trash is filled with `deadline`. The folder picker uses the system `.borderedProminent` style. Button sizes differ from `td-btn`: 28pt in panels and confirmations (Settings' on `code`, New linked task on `bg`) and for Open project file, 32pt in the sidebar, and Restore Items has a 12.5pt semibold `strong` label. Disabled buttons are drawn at half opacity. Appearance's segments are 26pt, with medium-weight labels when not selected.
- **Logbook** sits in the browser pane beside the editor rather than single-pane: Log Now in the header, the count of completed files still in place under it when there are any, then Completed today ("Still in place · logs tonight"), Waiting for open tasks (a completed project that still has open tasks, and its tasks), each day of the last week and each month. A task's box reopens it; a project shows a full ring in `done` (`muted` when cancelled). On iPhone it's pushed from Other, with Log Now and that count in the bottom bar. Completing a project with open tasks is a window sheet on the Mac and a confirmation dialog on iPhone, with Complete N Tasks and Cancel N Tasks, the project's own status the default.
- **Delete with attachments** is a window sheet on the Mac and a sheet on iPhone. A project's tasks are listed by title. An area that embeds no images still asks with an alert.
- **Attachments** sits in the browser pane beside a detail pane, as the Logbook does. Its list starts with nothing picked and its detail pane says "No image selected". A where-line names the live files, then "and N logged files" and "and N trashed files"; for an image only closed files embed it names them ("In the Logbook: …", "In Trash: …", "In the Logbook and Trash: …"), and for one nothing embeds it says "Not embedded anywhere · added <date>". Moving images to Trash asks only when a live file embeds one, or when how files use it isn't known yet (just renamed). Clean Up is a sheet on the Mac and iPhone; its ticks are fixed when it opens: all ticked, or all unticked while markdown files are still downloading from iCloud Drive (a note says so); an image that becomes a candidate while it's open starts unticked. On iPhone the list's search filters by image name or the title of a file that embeds it, and an image not downloaded is asked for when its screen opens, with Try Again if it fails.
- **Trash**: Restore returns files to `Ta Da/tasks/`, `Ta Da/projects/` and `Ta Da/areas/` (not each file's original folder), as each row's “restores to” line says. Images under a picked file show picked, but Restore's count is of the picked rows. An area's row is "Area · deleted with N projects and M tasks". Empty Trash and Delete Forever move files to the Mac's Trash, so the confirmation asks “Move N files to the Mac’s Trash?”. Delete Forever doesn't confirm.
- **File menu** items are in title case, as macOS menu commands are: Reveal in Finder, Delete Forever, Move 3 Tasks, Move 2 Projects, Schedule 3 Tasks, Delete 3 Tasks; Set Deadline… doesn't name the count, and Tags… (⌘T, after Set Deadline…) shows only for one file. The menu bar's File ▸ Reveal in Finder shows the picked or open files. Move opens the project menu (the area menu for a project) at the pointer in its place; ⌘P opens it under the open task's project chip, or under the first picked row. Schedule and Set Deadline… open the date menu the same way, as do ⌘S and ⌘D under the open file's date chip, the editor included; Tags… opens tagMenu the same way, as does ⌘T under the open file's + Tag chip, on an area too. The picked tasks pane shows only "N tasks selected".
- **Drag and drop**: task rows drag as their files, onto the sidebar's projects, areas, Loose tasks and Agenda (an area also takes dragged sidebar projects), and note rows onto the sidebar's Loose and notes folders, which take the `is-target` ring while a drag is over them, or into other apps as a drag from Finder would. Other apps get copies. A drag shows the dragged rows, stacked when several are picked.
- **Properties** are chips with status, move, area and date menus. Status, the parent (a task's project or area, a project's area), due date and deadline are 26pt chips, 12.5pt; a missing key is a dashed chip. An unresolved project or area is struck through in `muted`, and its menu offers Create Area for an area. An area's file has no chips, only its line. The type, createdDate and completedDate sit in an 11.5pt `muted` line below, with a project's ring and task count, so the project page's title has no ring. `contexts` and `repeat` aren't shown. Clear, Loose tasks and No area empty the key (`key:`) rather than remove it. A project's status menu adds Ongoing after Doing, drawn as the `[>]` box in `doing`, its dot's colour; a task's has no Ongoing.
- **Date menu** has a field above the calendar, the move menu's search field with `calendar` and "Type a date: fri, 3d, 25/12", which has the keyboard. Its right side shows, in `muted`, the day ↵ sets, or "No match · " and that day. The arrow keys don't move the day, and there are no footer key hints.
- **Project browser**: the progress ring and 24pt title, which a click turns into a field on `code` (Return or a click away renames, esc cancels), with Group and Open project file (an icon-only outlined button with a tooltip) on the right. Under them one 12.5pt `muted` line (`ProjectPropertyLine`): the status's dot and name, then the deadline and due date when set (icon in its tint, an overdue date's text in `deadline`), each a plain button that opens its menu under itself, `strong` while open; then the project file's own subtasks `n/m` and "n of m done". Keys the project doesn't have are set from the document pane's chips. An Ongoing project shows `checklist` in place of the ring and no "n of m done"; a tag page's project rows say Ongoing in place of its progress, and the file's quiet line says only Project. On iPhone the line is 15pt, its status a system menu and its dates opening the date sheet, with the Group menu leading the filter row under it. There is no summary. Its groups fold from a `chevron.down`/`chevron.right` before their name; folded groups are remembered per project.
- **Group and Filter**: Status, Date and Open groups use `CountGroupHeader`: the name in 15pt bold `strong` with its count in 12pt `muted` after it, and no status or date icons. Completed, Done and Cancelled are quiet: a 12.5pt semibold `muted` name with the count on the right. Under Project, a project's group is its 15pt ring and its name in 15pt bold `strong` over a hairline, with its area in 12pt `muted` only when no file has that area; projects in an area sit under the area's heading (`AreaGroupHeader`, its cube and name in 15pt bold `strong`) as `ProjectSubheader`s (a 15pt ring and 15pt bold `strong` name, as a project's group, without the rule). Tasks with no project or area lead the list without a header; a tag page keeps its Loose header for them. A task row keeps its tag glyph while filtering rather than naming the matched tags; the Agenda's day rows name their project or area under Status and Open whether or not tags are picked. The filter pill is hidden on a page where no file carries a tag. The filter menu's counts include a tag's children's files and list parents no file carries alone, as the tag tree does. On iPhone the headers are 20pt bold (a project under its area's heading has no rule) and a quiet header's name 15pt; the Group menu is the system menu (an inline picker, the default's subtitle "Default"), and the project file is a top-bar button in place of the Project file row.
- **Area page**: the 24pt cube and title (renames in place), Open area file, and an 11.5pt `muted` count of projects and open tasks. Its projects come first, one 34pt line each: the ring, the name in 14pt semibold `strong`, the deadline (overdue in `deadline`) and the open-task count in `muted`. The tasks filed straight to the area follow after a 22pt gap, then Completed under its quiet header, folded at first; New task in <area> ends the page. On iPhone project rows are the Tasks tab's. Deleting an area asks first, with the count of files that go.
- **Project page's Tasks table**: clicking a row opens the task beside the project's browser; its status, dueDate and deadline cells open the status and date menus under themselves, `surface` under the pointer, and its title renames in place. Rows are `code` under the pointer. New linked task adds an Untitled, Not Started row, scrolled into view with its title ready to type, and stays on the page.
- **Settings ▸ Vault**: Location (Change…, Reveal in Finder), Sync (iCloud Drive or local, and whether the folder is watched), Contents (task, project and area counts), and the `Ta Da/tasks/`, `Ta Da/projects/` and `Ta Da/areas/` folders. There is no Open another vault or Create new vault; Change… picks the folder.
- **Editor markdown** uses the engine's drawing: headings scale 2, 1.5, 1.17, 1, 0.83 and 0.67 times the 14pt body; code blocks are `code` line fills. Inline code is SF Mono at 12pt. A bubble that wraps reaches past the line's edge by its padding rather than pushing the text in.
- **Images** show drawn, the `</>` button on hover with its tooltip, the source shown, a missing image, and the ring of a selected image. An image draws only on a line of its own; an embed beside other text stays as text. SVGs aren't drawn and show as missing. On iPhone a tap puts the caret beside an image; there's no selected state.
- **Embed menu**: on iPhone Show in Files takes Reveal in Finder's place. On iPhone the menu opens at the press without lifting the image. Rename is a sheet in the delete dialog's layout, with the name field (its extension beside it) and the embeds it updates. The Mac's image dialogs are window sheets.
- **Table grid** keeps `td-md-table`'s frame, header row on `code` and hairlines, with cells editable in place. Each column is its widest cell's width, sharing the editor's width in proportion once the table is wider than it. A hovered row's grip (six `muted` dots) sits in the gutter left of it and a column's centred above its header; over a grip the pointer is an open hand (closed while dragging) and the row's or column's ring fades in. A selected row or column has a 2pt `accent` ring, a drag a 2pt `accent` line at the drop place. The header is bold; alignment doesn't change widths. iPhone shows the rendered image.
- **Link menu**: an empty `[[` lists every file by title, unlabelled, until one has been opened; `![[` lists images newest first, up to 50 rows, and shows SVGs with the `photo` symbol. An area shows its cube and Area on the right. On iPhone the list hides when nothing matches.

- **Callouts**: the caret's title line shows `> [!type]` in `muted` in the body font, not mono on `code`. Callout lines are 17pt high, as quote lines are, and a blank `>` line in a body is a full line. The slash menu's Callout inserts `> [!note] ` with the SF Symbol `text.bubble`.

- **Settings ▸ Hotkeys** has `arrow.counterclockwise` (Restore) and `xmark` (Clear). A taken shortcut other than ⌃Space gets a general warning naming its keys. A key's name is what it types on the layout it was recorded on, kept as recorded. Below Global, the app's other keys are listed, not editable, in the same rows as In Quick Entry: Files and views, Tasks, Editor, then In Quick Entry.

The type switch's icons are the task box, `ProgressRing` and `AreaIcon`. The panel's chips act as on a file, except that a tag chip's click and ⌘-click on a parent show that page in the main window behind the panel.

- **Tags**: a root tag lines up with Untagged, with a parent's chevron in the row's leading padding. tagAutocompleteMenu also lists parent tags carried by no file alone, as tagMenu does, and leaves out a tag only the open file's body carries once (the one being typed). On iPhone, notes show in tag screens (a Notes group), search and Trash, and open in the file screen with the Tags row and no status chips or status toolbar; it has no Notes tree.
- **Integrations**: a timed event that ends exactly at midnight shows All day on its last day. Past days list their events, and their reminders only while incomplete, so a past day shows just its overdue ones; the fetch covers the shown range, today forward to the end of next month, and at most a year ahead of today. A Show switch is disabled while its access is denied. Settings' icon is `calendar` in `deadline`. On iPhone, Settings ▸ Integrations lists each account as an uppercase `muted` label over its calendars or lists, and the Agenda's day leaves a 20pt gap between the events and reminders and a first task that has no group header.
- **Agenda** (the design's Agenda strip, month, day list, week list and iPhone pages): the strip and month run Monday to Sunday with ISO week numbers whatever the locale's first weekday; a week number is `muted` and, when its week note exists, `link`; a picked day or week is a filled 11pt-radius square in `strong` (`accent` for today) with `bg` text, and today's number is `accent`. Dots sit under a day's number: a ring in `due` for unchecked boxes in its daily note, a `due` dot for an open task due or at its deadline, a `muted` dot for an event or reminder. The Mac's strip scrolls sideways a week (or a month) at a time and a vertical trackpad swipe opens or closes the month; its title names the month of the week's Monday while a week shows. The iPhone's handle drags the strip between a week and the month, the month title also opens it, and a Today button shows while the Agenda isn't on today. A day's list is its full date, its note's row (or Start this day's note), events, reminders, then "Scheduled" with the Group menu and tag filter; a week's is its note row, a row per day (note's first paragraph, "n events · n due", dots) and Due this week. On iPhone today's note and a week's are cards with their checkbox lines before the first paragraph; other days' notes are rows. With no note the Mac's pane offers Create `<file name>` and "Uses the template set in Settings ▸ Daily notes.". New tasks and drops are due on the selected day, or today with a week picked. The Mac's ← → step the period while the list has the keyboard.

Tasks lists a Loose tasks row, then the loose projects and the areas with their projects, each on one line of at least 46pt with no chevron: a project's ring, its name in 17pt semibold `strong`, its deadline and open-task count; an area's cube, its name and "n projects · n tasks" in `muted`. Tags and Notes draw their trees on rounded `side` cards with a hairline border, a fold chevron before a row with children and 28pt of indent per level.
